## 1. `load_dataset("imdb")` 直接报错

**现象**

```
huggingface_hub.errors.HfUriError: Invalid HF URI 'hf://datasets/imdb@e62816.../.huggingface.yaml'.
Repository id must be 'namespace/name', got 'imdb'.
```

**原因**

HuggingFace 新版要求数据集 ID 是 `组织/名字` 两段式。`imdb` 是早期的单段旧名，虽然网页上还能跳转，但 `datasets` 3.x 之后拒绝解析。

**解决**

```python
# 错的
load_dataset("imdb", split="train[:3000]")
# 对的
load_dataset("stanfordnlp/imdb", split="train[:3000]")
```

**教训**

报错最后一行 `Repository id must be 'namespace/name'` 已经把答案写出来了。读报错要**从最后一行往上读**，那通常是真正的原因，上面的全是调用栈。

## 2. 训练 200 轮，loss 一动不动

**现象**

loss 每次打印都是同一个数，`w`、`b` 始终等于初始随机值。

**原因**

循环里只有 `backward()`，漏了 `optimizer.step()`。梯度算出来了，但从来没人拿它去更新参数。

```python
for epoch in range(200):
    y_pred = model(x)
    loss = loss_fn(y_pred, y_true)
    loss.backward()
    # ← 少了 optimizer.step()
    # ← 也少了 optimizer.zero_grad()
```

**解决**

补上 `step()` 和 `zero_grad()`。顺序：`forward → loss → backward → step → zero_grad`。

**教训**

**loss 完全不动 = 参数没被更新**。先查 step，再查学习率是不是 0，最后查优化器拿到的参数列表是不是空的。

## 3. MNIST 准确率卡在 10%，怎么训都不涨

**现象**

5 个 epoch 后准确率始终 ≈0.10（10 分类等于瞎猜）。

**原因**

`nn.CrossEntropyLoss()` 内部已经包含 `log_softmax`，我在模型 forward 里又加了一次 `softmax`，等于做了两次归一化。概率被压得几乎均匀，梯度信号极弱。

**解决**

模型最后一层直接输出 logits，不要接 softmax：

```python
# 错的
return torch.softmax(self.net(x), dim=-1)
# 对的
return self.net(x)
```

**教训**

**PyTorch 的 CrossEntropyLoss = log_softmax + NLLLoss**。看到"准确率恒等于 1/类别数"，第一反应就查是不是重复 softmax。

## 4. `y_pred = model` 而不是 `model(x)`

**现象**

```
TypeError: mse_loss() received an invalid combination of arguments
```

**原因**

`model` 是对象本身，`model(x)` 才是调用前向计算。写成 `model` 相当于把一个 `nn.Module` 对象当作预测结果传给了损失函数。

**解决**

```python
y_pred = model(x)      # nn.Module 重载了 __call__，等价于 model.forward(x)
```

**教训**

`nn.Module` 实例后面忘了括号，是最常见的低级错误之一。报错里出现 "received an invalid combination of arguments"，先看传给 loss 的东西到底是不是张量。

## 5. 微调后模型"变笨了"，问什么都回客服话术

**现象**

LoRA 微调 Qwen2.5-0.5B（24 条客服问答、3 epoch、batch 2）后，训练集上的回答很标准，但换成训练集外的问题（"今天天气怎么样"）也开始回"请您提供订单号"。

**原因**

24 条 ÷ batch 2 = 12 步/epoch × 3 = **总共 36 次参数更新**，模型足以把每条答案背下来。loss 掉到 0.3 以下不是"学得好"，是"背得熟"。这叫风格固化（过拟合的一种表现）。

**解决**

- `EPOCHS` 3 → 1，`LR` 2e-4 → 1e-4
- 数据从 24 条扩到 100 条以上，同一意图要有十几种说法
- 加域外测试：问 3 个训练集里完全没有的问题，看通用能力有没有被破坏

**教训**

**LoRA 限制的是"改多少参数"，不是"会不会过拟合"**。参数少 ≠ 不会背答案，数据少照样过拟合。判断标准永远是验证集/域外表现，不是训练 loss。

## 6. 模型编了一条不存在的折扣政策

**现象**

问"能便宜一点吗"，LoRA 后的模型回答：

> 我建议您在原价基础上再打 5-10% 的折扣，具体以客服确认为准。

训练数据里只有"有满减活动"，**没有任何关于 5-10% 的数字**。

**原因**

微调让模型学会了"客服该有的语气"，于是它顺着这个语气把内容也编了出来。**语气是学来的，事实是编的**——这是微调做知识型任务的固有风险。

**解决**

这不是调参能修的。正确做法是把"事实"从模型权重里拿出来，改成检索：让模型只根据检索到的真实文档回答，并在 prompt 里明确"资料里没有就说没有"（这就是第 3 周 RAG 的动机）。

**教训**

**微调解决"怎么说"，RAG 解决"说什么"。** 想让模型记住会变化的事实，微调是错的方向。

## 7. LoRA 训练时 loss 正常，但模型没学会回答

**现象**

训练 loss 一路下降，但生成的回答和训练目标完全不搭，甚至把提问原样复述出来。

**原因**

生成模型的训练样本是"提问 + 回答"拼成的整串，如果不对**提问部分做 label 掩码**，模型会连"怎么提问"一起学，而且提问占的 token 更多，loss 主要被提问部分主导。

**解决**

提问部分的 label 全部设为 `-100`，PyTorch 的交叉熵会跳过这些位置：

```python
labels = [-100] * len(prompt_ids) + answer_ids
```

**教训**

**分类任务不需要掩码（一条样本一个标签），生成任务必须要**。这是两类任务在数据处理上最本质的差别。

## 8. `imshow` 画出来的图变成一条线

**现象**

`ax.imshow(images[i])` 显示成一条 1 像素高的彩色细线，而不是手写数字。

**原因**

`images[i]` 形状是 `(1, 28, 28)`（带通道维），而 `imshow` 期望灰度图是 `(高, 宽)`。它把通道维的 1 当成了高度。

**解决**

```python
ax.imshow(images[i].squeeze(), cmap="gray")   # (1,28,28) → (28,28)
```

**教训**

**单张图送进 matplotlib 之前先 `squeeze()`**。同类问题：`(N,1,28,28)` 的批次不能直接画，要先取出一张。

## 9. PyCharm 自动导入，往代码里塞了不存在的模块

**现象**

打包代码时扫到两行莫名其妙的导入：

```python
from langchain_classic.chains.constitutional_ai.prompts import examples
from langchain_classic.chains.question_answering.map_reduce_prompt import messages
```

代码里根本没用过 `examples` / `messages` 这两个名字，而且环境里没装 `langchain_classic`，直接 `ImportError`。

**原因**

PyCharm 的自动补全在输入 `examples = ...` 时误触了"导入建议"，把同名的符号从 langchain 里导了进来。第二处更糟：`messages` 是后面要用的变量名，导入后被覆盖。

**解决**

删掉这两行，改成正常的变量定义。

**教训**

**提交前扫一遍 import**：

```bash
grep -rn "langchain\|^from [a-z]*\.[a-z]" --include="*.py" .
```

自动导入是 IDE 的便利，也是隐性炸弹——它引入的依赖你的环境里可能根本没有。
