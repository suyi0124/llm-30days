# 数据预处理对照表

> 用途：把 Day 3 / 9 / 10 / 13 四种“看起来完全不一样”的数据处理，还原成同一条管道。
> 看这张表比重新读四份代码快 10 倍。

---

## 一、核心：所有预处理只为了一件事

模型的输入永远是**张量**，而且**形状必须规整**（同一个 batch 里每条长度一致）。
所以无论数据源是图片、文本还是表格，都走同一条管道：

```
原始数据  →  ① 取一条  →  ② 变成数字  →  ③ 对齐形状  →  ④ 拼成 batch  →  模型
```

**四步永远不变，变的只是每一步调用的函数。**

---

## 二、四个场景对照

| 阶段 | Day 3 图像（MNIST） | Day 9/10 文本分类（IMDb） | Day 13 文本生成（客服） |
|---|---|---|---|
| **① 取一条** | `dataset[i]` → `(PIL图, 标签)` | `dataset[i]` → `{'text','label'}` | `DATA[i]` → `(问, 答)` 元组 |
| **② 变数字** | `transforms.ToTensor()` → `(1,28,28)`，像素除 255 | `tokenizer(text)` → `input_ids: (L,)` | `tokenizer(问题+答案)` → `ids: (L,)` |
| **③ 对齐形状** | 图像天生都是 28×28，**不用对齐** | `padding="max_length", max_length=256` | 手写 `collate()` 补到 batch 内最长 |
| **④ 拼 batch** | `DataLoader(batch_size=64)` 全自动 | `DataLoader` + `set_format("torch")` | 手写 `collate()` + `torch.tensor` |

四行的代码长度差很多，但**每一列都在回答同样四个问题**。

---

## 三、为什么看起来差别这么大（4 个真实原因）

**1. 数据本质不同**
像素是连续数值 → 只需要除以 255 归一化。
文字是离散符号 → 必须先查词表变成整数 ID（这是 Day 8 的分词器）。

**2. 是否天然等长**
图像都是 28×28，天生整齐，直接 `stack` 就行。
文本从 3 个字到 3000 个字都有 → **必须 padding**，并用 `attention_mask` 标记哪些是填充。

**3. 标签形式不同**
分类任务：一条样本 = 一个整数（0 或 1）。
生成任务：一条样本 = **每个位置一个目标 token**，而且提问部分要设成 `-100` 屏蔽掉。

**4. 库的封装程度不同**
图像有 `torchvision` 全自动（Dataset + transform 都给你写好了）。
文本有 HuggingFace 半自动（tokenizer 给你，但 batch 拼装要自己写）。
自定义任务 → 全手写。

> 所以“每次都不一样”的本质是：**库帮你做了多少，剩下的你就要自己做。**

---

## 四、遇到新任务，只问四个问题

拿到任何新数据，不要急着抄代码，先回答这四句：

1. **一条数据长什么样？** → 打印 `dataset[0]`，看清楚字段和类型
2. **怎么变成数字？** → 图像 `ToTensor` / 文本 `tokenizer` / 表格 `astype(float)`
3. **长度一致吗？** → 不一致就必须 `padding` + `mask`
4. **batch 怎么拼？** → 库能自动就自动；不能就写 `collate`，返回一个字典的批张量

四个问题回答完，代码自然就出来了。**这比背 API 有用一百倍。**

## 五、Python 语法急救包（这 10 条够用整个月）

你在这些代码里见到的“看不懂的语法”，99% 是下面 10 个之一：

| # | 语法 | 长什么样 | 一句话解释 |
|---|---|---|---|
| 1 | 下标 / 切片 | `dataset[0]` `text[:50]` `labels[:9]` | 取第几个；`[a:b]` 取 a 到 b-1 |
| 2 | 字典取值 | `item["text"]` `data['usage']` | 按 key 拿 value |
| 3 | 列表推导式 | `[stoi[c] for c in s]` | 一行版 for 循环 + append，结果是个列表 |
| 4 | lambda | `lambda x: len(x["text"]) < 500` | 只有一句 return 的匿名小函数 |
| 5 | f-string | `f"loss={loss:.4f}"` | 字符串里插变量，`:` 后面是格式 |
| 6 | 元组解包 | `fig, axes = plt.subplots(3,3)`<br>`for x, y in loader:` | 右边是几个值，左边就摆几个变量接 |
| 7 | `**` 解包字典 | `model(**inputs)` | 把 `{"a":1}` 拆成 `model(a=1)` |
| 8 | enumerate | `for i, ax in enumerate(axes.flat)` | 遍历时同时给你下标和元素 |
| 9 | with 语句 | `with torch.no_grad():` | 进入一个“临时状态”，退出自动恢复 |
| 10 | 张量小工具 | `.shape` `.item()` `.tolist()` | 看形状 / 转成数字 / 转成列表 |

**学这 10 条的方法**：不用背定义，去找“它在哪个文件第几行出现过”，把那行改坏一次看报错——比读文档快。

## 七、一个验证练习（10 分钟）

打开 `day13_lora_qwen.py`，把 `build_example` 换成官方模板写法：

```python
def build_example(q, a):
    msgs = [{"role": "user", "content": q}]
    prompt = tokenizer.apply_chat_template(msgs, tokenize=False, add_generation_prompt=True)
    full = prompt + a + "<|im_end|>\n"
    ids = tokenizer(full, add_special_tokens=False)["input_ids"][:256]
    p_len = len(tokenizer(prompt, add_special_tokens=False)["input_ids"])
    labels = [-100] * p_len + ids[p_len:]
    return {"input_ids": ids, "labels": labels}
```

跑通后你会明白：**换一种数据格式，只有“② 变数字”这一步变了，管道结构一点没动。**
