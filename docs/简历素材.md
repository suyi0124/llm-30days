## 一、项目经历（简历主体，挑 2 个写）

### 项目 1：从零实现 mini GPT（原理类，体现"懂底层"）

**一句话**：用 PyTorch 从零实现字符级 GPT，含嵌入、因果自注意力、训练与自回归生成，参数量 5 万，CPU 可训练。

- 手写 `Head` 类实现 `softmax(QKᵀ/√d_k)V`，用 `masked_fill(-inf)` 实现因果掩码，验证"去掉掩码后 loss 异常下降但生成乱码"的现象
- 实现字符级 tokenizer（`stoi`/`itos`）与错位采样（x 与 y 错一位），理解"看前面猜下一个"的训练目标
- 通过消融实验定位两个关键组件的作用：删位置嵌入 → 生成连贯性明显下降；`block_size` 从 32 降到 8 → 上下文能力受限
- 结果：loss 从 4.2（≈ln 词表大小，等于瞎猜）降到 1.0，生成文本出现 `the`/`to`/`that` 等真实词形 ⚠️ 待核实（对照你最后一次运行的输出）

**面试可讲**：为什么除以 √d_k、掩码为什么用 -inf 而不是 0、为什么训练时 x 和 y 要错一位。

---

### 项目 2：LoRA 微调 Qwen2.5-0.5B 做客服话术定制（工程类，体现"会落地"）

**一句话**：用 peft 对 Qwen2.5-0.5B 做 LoRA 微调，仅训练 0.2% 参数，adapter 体积 15MB（完整模型 1GB）。

- 配置 `r=8 / alpha=16 / target_modules=q,k,v,o_proj`，冻结底座权重，在注意力投影层挂低秩矩阵
- 对训练样本做 **label 掩码**（prompt 部分设 -100），使 loss 只在回答部分计算，避免模型学习"怎么提问"
- 用 `disable_adapter()` 做前后对比，观察到回答从"百科式长段落"收敛为"客服式短句"
- 发现并定位过拟合问题：24 条样本 3 epoch（36 次参数更新）导致风格固化，问域外问题也回客服话术；通过降 epoch、降学习率、扩充数据解决
- 发现微调的固有问题：模型学会了客服语气，但编造了训练数据中不存在的"5-10% 折扣"政策 → 成为后续引入 RAG 的直接动机

**面试可讲**：LoRA 为什么省参数、r 和 alpha 的作用、为什么要做 label 掩码、过拟合怎么发现怎么修、"微调会编事实"这件事怎么理解。

### 项目 3（可选）：BERT 情感分类微调

**一句话**：微调 `distilbert-base-uncased` 做 IMDb 情感分类，3000 条训练样本、2 epoch，测试准确率约 88%（未微调基线约 75%）⚠️ 待核实

- 处理变长文本：`padding="max_length"` + `attention_mask`，理解 mask 在注意力中的作用
- 学习率设为 2e-5（比从头训练小 50 倍），避免灾难性遗忘
- 做三组对照实验：学习率放大 100 倍 → loss 发散；训练量降到 500 条 → 准确率降至 80% 左右；冻结主体只训分类头 → 速度提升约 3 倍、准确率略降（LoRA 的思想雏形）

## 三、面试高频问题的答案雏形

**Q：介绍一下你的项目**

> 我先从底层做起，用 PyTorch 从零实现了一个字符级 GPT，把注意力、掩码、位置嵌入这些跑通；然后用 HuggingFace 做了 BERT 和 LoRA 微调，踩到了过拟合和"微调会编事实"的坑；现在在做 RAG，想解决"知识更新和可溯源"的问题。

（三段递进：懂原理 → 会工程 → 知道边界在哪。比罗列技术栈强得多。）

**Q：RAG 和微调怎么选？**

> 微调解决"怎么说"，RAG 解决"说什么"。知识频繁更新、需要出处、数据规模大 → RAG；要固定风格和输出格式 → 微调。我自己踩过：LoRA 训完语气对了，但编了一条训练集里没有的折扣政策——这就是我转去做 RAG 的原因。

**Q：微调踩过什么坑？**

> 最典型的是过拟合。24 条数据 3 个 epoch，只有 36 次参数更新，模型直接把答案背下来了，问域外问题也回客服话术。判断依据不是训练 loss（它很低），而是换问法就崩。后来降 epoch、扩数据才稳定。

**Q：为什么用 LoRA 而不是全量微调？**

> 5 亿参数全量微调要几十 GB 显存，我只有 CPU。LoRA 只训 0.2% 参数（注意力四个投影层的低秩矩阵），10 分钟能跑完，adapter 只有 15MB。而且底座不动，`disable_adapter()` 就能回到原版，一个底座可以挂多个 adapter 切任务。

**Q：注意力为什么要除以 √d_k？**

> 点积的方差随维度线性增长，不缩放的话分数会很大，softmax 之后接近 one-hot，梯度几乎为 0。除以 √d_k 把方差拉回 1，让 softmax 工作在梯度健康的区间。
